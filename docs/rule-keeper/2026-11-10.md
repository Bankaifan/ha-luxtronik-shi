## Recurring model steps that a script should do

### 1. Label creation before each label (orchestrator, scout)
- Where: `orchestrator.yml` prompt ("Before adding any label run `gh label create <label> --force`"),
  `scout.yml` prompt ("`gh label create idea --force` first", "one call per label").
- Why: every run repeats the same fixed command. `setup.yml` creates the same labels, but it is manual, so it is not a guarantee.
- Proposal: `tools/ensure_labels.py` (idempotent `gh label create --force` for the label set) as a no-model step before
  the model step. Delete the prompt sentences.
- Runs per week: orchestrator up to 7 (daily cron, plus label events; model runs only when work exists: `open`);
  scout about 0.25 (monthly cron).
- Files: `.github/workflows/orchestrator.yml`, `.github/workflows/scout.yml`, `tools/ensure_labels.py` (new).

### 2. Rule-keeper "stop if a PR is open" (rule-keeper)
- Where: `rule-keeper.yml` prompt: "first run `gh pr list --state open --search head:agent/rule-keeper-` and stop if one is open".
- Why: a fixed query with a decision that needs no judgement.
- Proposal: `tools/rule_keeper_gate.py` before the `claude` step. It writes `skip=true` when an open PR exists, and the
  model step is skipped on that output.
- Runs per week: 1 (Monday cron).
- Files: `.github/workflows/rule-keeper.yml`, `tools/rule_keeper_gate.py` (new).

### 3. Handover skip checks (orchestrator)
- Where: `orchestrator.yml` prompt: today's `head:agent/orchestrator-handover-<date>` lookup, then the open-handover lookup.
- Why: fixed queries and skip decisions, run by the model on every run.
- Proposal: the existing "Count work (no model)" step writes `handover=write|skip` to its outputs. The prompt reads it.
- Runs per week: `open` (daily cron, up to 7).
- Files: `.github/workflows/orchestrator.yml`, `tools/prefilter.py` or a small new script.

### 4. Design task label clean-up (orchestrator, `orchestrator.md`)
- Where: "After the merge remove `agent:dev` and `needs-human` from the source issue". Done by the model.
- Why: `design_parents.py` and `status.py` already remove `agent:dev` at other points. The model step is the only
  place that removes `needs-human` from a design source issue.
- Proposal: the status run removes both labels when a `docs/design/` PR merges that names the issue.
- Runs per week: `open` (design PRs are rare: one design-only PR, #75, in the last 30 merged).

## Rules and checks that conflict or do nothing

### 5. Dead version check in `make check`
- `Makefile` runs `tools/check/check_version.py`. It reads `VERSION_FILE` or a `VERSION` file in the root. Neither exists,
  so it prints "skipped" on every run. The real check is `tools/check_version.py`, which the Makefile runs too.
- Proposal: delete `tools/check/check_version.py` and its Makefile line, or set `VERSION_FILE` if it is meant to check something.
- Runs per week: every `make check` run (validate and agent runs): `open`.
- Files: `Makefile`, `tools/check/check_version.py` (template-managed).

### 6. Developer role and developer allowlist disagree on Bash
- `.agents/roles/developer.md`: Bash only for git, make, python3, pytest, ruff, actionlint, zizmor and a few `gh` calls;
  "not `ls`/`cat`/`find`".
- `agent-dev.yml` `--allowedTools`: also `ls`, `cp`, `mkdir`, `diff`, `cmp`, `wc`, `gh run view`, `gh release view/list`.
- Proposal: align the role text with the allowlist, or cut the allowlist. Any allowlist change goes through the security reviewer.
- Runs per week: agent-dev runs: `open`.
- Files: `.agents/roles/developer.md`, `.github/workflows/agent-dev.yml`.

### 7. Duplicate `needs-human-note` comments
- PR #91 and PR #115 each carry the same `<!-- needs-human-note <sha12> -->` comment twice.
  The marker constant is `tools/ci/risk.py:172`.
- Proposal: `tools/ci/risk.py` checks for an existing note with the same head-SHA marker before it posts.
- Affected: 2 of the last 30 merged PRs. Runs per week: `open`.
- Files: `tools/ci/risk.py` (template-managed).
