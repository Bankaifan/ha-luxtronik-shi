## New findings

### R1. A host git setting makes `make check` red (repeated failure)
- Evidence: the same 9 failures are cited in 5 of the last 30 merged PRs (#224, #231, #233, #235, #237). Each was merged
  with "not caused by this change". Reproduced here.
- Cause: the train tests run `git` through `train.git_env()` without isolating the host's global config. The runner sets
  `safe.bareRepository=explicit`, so the bare origin repo is refused.
- Proposal: `git_env()` adds `GIT_CONFIG_COUNT=1`, `GIT_CONFIG_KEY_0=safe.bareRepository`, `GIT_CONFIG_VALUE_0=all`
  (git 2.31+), so the tests do not depend on the host. No check is weakened. `GIT_CONFIG_GLOBAL=/dev/null` would also
  drop the test identity, so do not use it without checking.
- Optional: run the Makefile checks with `$(MAKE) -k` so one red test does not hide drift and budget results.
- Runs per week: `open` (every agent run that runs `make check` locally).
- Files (template): `tools/train.py` (`git_env`), `tests/agent/test_train.py` only if the environment fix is not enough.

### R2. "Body max 5 lines" is not checked and conflicts with the Friction section
- Rule text: AGENTS.md "Commits and PRs" (body "at most 5 lines"), `.agents/roles/developer.md` ("body max 5 lines"),
  and the rule-keeper prompt.
- `developer.md` also asks for an optional `## Friction` section at the end of the body, which the cap does not mention.
- `tools/check/check_pr_form.py` checks only: non-empty body, no attribution, no closing keyword on design PRs, the issue
  reference, and an ASCII title. It counts no lines, and its docstring accepts `## Friction`.
- Failure: a body of 8 lines plus Friction passes CI while the rule says 5.
- Proposal: `check_pr_form.py` counts the lines before a `## Friction` heading and fails above 5. AGENTS.md and
  `developer.md` say "excluding the optional `## Friction` section". Script first, text second.
- Runs per week: `open` (every agent PR).
- Files (template): `tools/check/check_pr_form.py`, `AGENTS.md`, `.agents/roles/developer.md`.
